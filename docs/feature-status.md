## 서비스 구성

| 서비스 | 역할 |
| --- | --- |
| `frontend` | React SPA. 사용자가 보는 모든 화면 |
| `bff` | 브라우저 전용 진입점. 세션/토큰 보관, 하위 서비스 호출 차단기 |
| `backend` | 핵심 도메인. 권한 판단은 전부 여기서 한다 |
| `ai` | FastAPI. 검색(RAG)과 LLM 호출. 색인 worker는 별도 프로세스 |
| `auth` | 인증 서비스 |
| `stt` | 실시간 전사 서비스 |
| `cert-loader` | mTLS 인증서 로더 (Go) |

핵심 원칙: **프론트엔드는 AI 서버를 직접 부르지 않는다.** 항상 Backend가 권한을 확인한 뒤 넘긴다.

- [x] 모든 기기 로그아웃, 계정 탈퇴

주의: 서명 provider가 `disabled`면 토큰 발급이 **막힙니다**(fail-closed). 실제 서명 인프라가 없으면 local legacy auth 프로필을 씁니다.

### 2. 프로젝트 / 대시보드 (FR-DASH, FR-PERM, FR-OWN)

### 3. 회의 등록 / 권한 (FR-MREG, FR-ACL)

- [x] 회의 생성, 참가자 등록, 초대 링크

`member` 참가자는 프로젝트 멤버여야 합니다. 회의만 초대받은 사람은 `guest`입니다.

마지막 항목은 가짜 카메라로 대신할 수 없어 자동화가 불가능합니다.

### 5. STT 전사 (FR-STT)

- [x] 실시간 전사 시작/종료

기본 provider는 Soniox, 실패 시 OpenAI로 넘어갑니다. 검증할 때는 fallback을 막아야 합니다 — 안 그러면 Soniox가 실패해도 OpenAI가 전사해서 통과처럼 보입니다.

### 6. 회의록 / 보고서 (FR-RPT)

- [x] 전사 기반 AI 회의록 생성 (`T449`)

전체 흐름: **전사 → AI 생성 → 확정 → 색인**. 확정된 회의록은 별도 문서를 만들지 않고 회의 자료로 색인됩니다.
