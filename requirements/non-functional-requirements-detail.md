# Non-Functional Requirements Detail

Google Sheets 비기능요건(NFR) 시트의 전체 우선순위(P0/P1/P2) 상세 기준 로컬 스냅샷이다.
각 항목은 원본 Sheet의 측정지표/기준, 상세 기준, 측정 방법, 적용/예외 조건, 검증 주기, 미결정 사항을 보존한다.

## 보안 (Security)

### NFR-SEC-01 비밀번호는 단방향 해시로 저장한다

- 분류: 보안
- 우선순위: `P0`
- 측정지표/기준: bcrypt/argon2, 평문 미저장
- 비고: -
- 상세 기준: 비밀번호는 평문, 양방향 암호화, 로그 출력 없이 단방향 해시로만 저장한다.
- 측정 방법: DB 샘플 점검과 가입/변경 API 테스트로 확인한다.
- 적용/예외 조건: 기존 마이그레이션 계정도 최초 변경 시 동일 정책을 적용한다.
- 검증 주기: 릴리즈 전/보안 점검 시
- 미결정 사항: bcrypt cost 또는 argon2 파라미터 확정

### NFR-SEC-02 refresh 토큰 원문을 저장하지 않는다

- 분류: 보안
- 우선순위: `P0`
- 측정지표/기준: 브라우저/로그 미저장, BFF 암호화 저장, Auth Service hash + revoke 저장
- 비고: -
- 상세 기준: refresh 토큰은 브라우저 저장소·브라우저 응답·로그에 남기지 않는다. 복호화가 필요한 BFF는 Token Vault에 KMS 기반 암호문만 저장하고 Auth Service는 원문 대신 hash와 revoke 상태만 저장한다. 평문은 BFF가 Auth Service에 refresh 요청을 보내는 프로세스 메모리에만 일시적으로 존재할 수 있다.
- 측정 방법: 브라우저 저장소/네트워크 응답, BFF Redis/Token Vault 암호문, Auth Service DB 컬럼, 로그, 토큰 재사용 테스트를 점검한다.
- 적용/예외 조건: BFF Token Vault의 복호화 가능한 암호문은 Auth Service에 토큰을 제시하기 위해 허용하는 유일한 서버 저장 예외다.
- 검증 주기: 릴리즈 전/침투 테스트 시
- 미결정 사항: 없음. 이미 사용된 refresh 재사용은 동시 grace 없이 해당 AuthSession family 전체를 폐기한다.

### NFR-SEC-03 소셜 ID token을 서버에서 검증한다

- 분류: 보안
- 우선순위: `P0`
- 측정지표/기준: signature/expiry/audience 검증
- 비고: -
- 상세 기준: Google ID token은 서버에서 signature, expiry, audience, issuer를 검증한다.
- 측정 방법: 위조/만료/audience 불일치 토큰 테스트로 확인한다.
- 적용/예외 조건: 로컬 개발 환경은 테스트용 client id만 허용한다.
- 검증 주기: OAuth 변경 시/릴리즈 전
- 미결정 사항: 허용 client id 목록 관리 방식

### NFR-SEC-04 통신 구간을 암호화한다

- 분류: 보안
- 우선순위: `P0`
- 측정지표/기준: HTTPS/TLS 적용
- 비고: -
- 상세 기준: 모든 운영 트래픽은 HTTPS/TLS를 사용한다. BFF/Auth/Resource Service 내부 호출은 mTLS와 SPIFFE workload identity로 양방향 인증하고 NetworkPolicy와 endpoint allowlist를 함께 적용한다.
- 측정 방법: 배포 URL, API 요청, mixed content 여부를 확인한다.
- 적용/예외 조건: 로컬 개발 환경은 예외로 둘 수 있다.
- 검증 주기: 배포 전/인프라 변경 시
- 미결정 사항: 서비스 메시 제품과 인증서 발급 구현은 Q-012/T040에서 확정한다. workload identity 계약은 mTLS/SPIFFE로 고정한다.

### NFR-SEC-07 에러 응답에 내부정보를 노출하지 않는다

- 분류: 보안
- 우선순위: `P1`
- 측정지표/기준: 예외/stack/SQL 미노출, 고정 code
- 비고: -
- 상세 기준: 에러 응답은 내부 stack, SQL, provider raw error를 노출하지 않는다.
- 측정 방법: 강제 예외 테스트와 응답 본문 점검으로 확인한다.
- 적용/예외 조건: 서버 로그에는 추적용 requestId를 남기되 사용자 응답에는 제한한다.
- 검증 주기: 릴리즈 전/오류 핸들러 변경 시
- 미결정 사항: 공개 에러코드 체계

### NFR-SEC-08 CSRF/CORS를 통제한다

- 분류: 보안
- 우선순위: `P1`
- 측정지표/기준: 허용 출처 제한
- 비고: -
- 상세 기준: 브라우저와 Web BFF는 동일 Origin을 기본으로 하고 쿠키 인증을 사용하는 모든 상태 변경 요청은 CSRF token을 검증한다. CORS가 필요한 예외 Origin은 명시 allowlist로만 허용한다.
- 측정 방법: 허용되지 않은 origin 요청과 인증 요청 테스트로 확인한다.
- 적용/예외 조건: 브라우저-BFF 쿠키 API에는 CSRF를 적용하고 BFF-내부 서비스 Bearer API에는 브라우저 CORS를 허용하지 않는다.
- 검증 주기: 배포 환경 변경 시
- 미결정 사항: 없음(`specs/002-bff-auth-msa/contracts/browser-auth-api.md`에서 전달 header와 운영/로컬 cookie profile 확정)

## 권한 / 접근 제어 (Authorization)

### NFR-AZ-01 권한 필터를 검색·컨텍스트 조립 이전에 적용한다

- 분류: 권한
- 우선순위: `P0`
- 측정지표/기준: RAG/검색 前 선(先)필터
- 비고: 원칙5
- 상세 기준: AI/RAG 검색 전에 사용자 권한으로 후보 데이터를 선필터링한다.
- 측정 방법: 권한 없는 회의 청크 삽입 테스트로 검색 결과를 확인한다.
- 적용/예외 조건: 프롬프트 단계 숨김만으로는 충족하지 않는다.
- 검증 주기: RAG 변경 시/릴리즈 전
- 미결정 사항: 권한 필터 구현 위치

- 비고: -

- 측정 방법: Space 멤버지만 회의 ACL이 없는 사용자와 owner/admin override 케이스를 테스트한다.

- 검증 주기: 권한 기능 배포 전
- 미결정 사항: 평가 순서 상세

## 성능 (Performance)

### NFR-PERF-01 API 응답시간 목표를 만족한다

- 분류: 성능
- 우선순위: `P1`
- 측정지표/기준: p95 목표(예: <500ms)
- 비고: 목표값 확정
- 상세 기준: 일반 API는 목표 p95 응답시간을 만족해야 한다.
- 측정 방법: APM, 서버 로그, 부하 테스트로 p95를 측정한다.
- 적용/예외 조건: AI/파일 다운로드/화상회의 API는 별도 기준을 적용한다.
- 검증 주기: 릴리즈 전/월간
- 미결정 사항: 확정 목표값

### NFR-DATA-05 토큰 저장 위치를 규정한다

- 비고: -
