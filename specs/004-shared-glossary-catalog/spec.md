# Spec: 분야별 공용 용어 사전 (Shared Glossary Catalog)

## 문제

현재 용어 사전은 Space가 직접 등록한 용어(`domain_terms`)만 조회한다. 신규 Space의 사전은 비어 있고, 회의 중 모르는 용어를 선택하면 사실상 모든 요청이 AI 게이트웨이로 넘어간다.

사전을 미리 채우려면 그 용어를 이미 알고 있어야 하므로, 정작 설명이 필요한 순간에 사전은 비어 있다. `FR-TERM-02`(등록 용어는 LLM 미호출)가 실질적으로 동작하지 않고, `NFR-COST-01`의 비용 억제 효과도 얻지 못한다.

## 사용자 가치

- 신규 Space도 첫 회의부터 채워진 용어 사전을 사용한다.
- 관리자가 분야별로 용어를 관리하고, Space는 자기 업무 분야만 골라서 제공받는다.
- 등록 용어는 LLM을 거치지 않으므로 응답이 빠르고 AI 호출 비용이 줄어든다.
- 분야를 좁히므로 같은 약어가 분야마다 다른 뜻을 갖는 경우(예: 패션의 `SS`) 엉뚱한 분야의 정의가 섞이지 않는다.

## 확정 사항 (2026-07-27, 사용자 결정)

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| 저장 구조 | 공용 사전을 `shared_domain_terms`로 분리하고 `domain_terms`는 변경하지 않는다 | 기존 제약조건·유니크 인덱스·API가 깨지지 않고, 관리자용과 사용자용 권한을 분리하기 쉽다 |
| 재정의 | 같은 용어가 양쪽에 있으면 Space 등록 용어가 우선한다 | 조직마다 같은 단어를 다르게 쓰는 현실을 반영한다 |
| 구독 단위 | Space 단위로 분야를 선택한다 | 같은 회의 참여자가 서로 다른 설명을 보는 상황을 막는다 |
| 기본값 | 구독 설정이 없으면 모든 분야를 구독한 것으로 본다 | 설정 전에도 사전이 비어 있지 않다 |
| 범위 | 스키마 + 시드 데이터 + 조회 연동까지 | 관리자 CRUD API와 구독 설정 UI는 후속 작업으로 분리한다 |

## 확장 확정 사항 (2026-07-27)

| 결정 | 내용 | 근거 |
| --- | --- | --- |
| Space 생성 | 활성 공용 용어 분야를 checkbox로 여러 개 선택한다 | 한 프로젝트가 IT와 금융처럼 여러 업무 분야를 함께 가질 수 있다 |
| 기타 분야 | `기타` 선택 시 한 개 이상의 사용자 입력 분야명을 Space 범위로 저장한다 | 사용자 입력으로 전역 공용 카탈로그를 오염시키지 않는다 |
| 중복 검증 | category ID와 사용자 입력 분야명은 각각 중복을 거부하고, 사용자 입력이 기존 분야명과 같아도 거부한다 | 같은 선택이 여러 경로로 저장되는 것을 막는다 |
| 기존 Space 호환 | 선택 행이 없는 기존 Space는 계속 전체 분야 구독, 행이 있는 Space는 `enabled=true` 분야만 구독으로 해석한다 | 기존 Space를 유지하면서 신규 Space의 명시적 선택과 이후 추가 분야의 비자동 구독을 보장한다 |
| 용어사전 노출 | Space 용어사전 목록에 Space 등록 용어와 구독 중 공용 용어를 함께 표시한다 | 공용 사전이 존재하지만 빈 화면으로 보이는 문제를 해결한다 |
| 회의 화면 노출 | 같은 통합 목록을 자막 하이라이트에 사용하고 공용 용어는 읽기 전용으로 설명한다 | 목록과 회의 설명의 사전 범위를 일치시킨다 |
| Knowledge 노드 | 활성 통합 용어를 Knowledge 그래프의 `GLOSSARY` 노드로 표시하고 선택 시 정의를 보여 준다 | 프로젝트에서 쓰는 용어를 회의·공식 지식과 함께 탐색할 수 있어야 한다 |

### 확장 범위

- `GET /api/v1/glossary/categories` 카탈로그 조회.
- `POST /api/v1/spaces`에 `glossaryCategoryIds`, `customGlossaryCategories` 추가.
- 신규 Space의 분야 선택을 `space_glossary_categories`에 명시적으로 저장.
- `space_custom_glossary_categories` 신설(V33).
- `GET /api/v1/spaces/{spaceId}/terms`에서 구독 공용 용어를 읽기 전용 항목으로 함께 반환.
- `GET /api/v1/spaces/{spaceId}/knowledge/graph`에서 같은 통합 ACTIVE 목록을 `GLOSSARY` 노드로 반환.
- Space 생성 화면 두 곳에 다중 선택과 `기타` 입력 UI 추가.
- Live Transcript가 통합 용어 목록을 사용해 공용 용어도 선택 가능하게 표시.

### Knowledge 노드 인수 기준

- Space 등록 ACTIVE 용어와 구독 분야의 공용 ACTIVE 용어가 각각 안정적인 ID를 가진 노드로 보인다.
- 같은 이름의 Space 용어와 공용 용어가 있으면 Space 용어 노드 하나만 보인다.
- 용어 노드를 선택하면 용어 정의를 확인할 수 있다.
- `nodeTypes=GLOSSARY` 필터를 지원하며 Space 접근 권한 검사를 통과한 사용자에게만 반환한다.
- 이번 단계에서는 용어를 embedding하지 않으므로 의미 유사도 연결선은 만들지 않는다. 연결선 생성과 Project AI RAG 편입은 별도 색인 작업으로 남긴다.

## 범위

### 이번 구현
- `glossary_categories`, `shared_domain_terms`, `space_glossary_categories` 테이블 신설 (V30).
- 분야 9개와 공용 용어 184개 시드 (V32).
- `MeetingTermExplanationService.explain()` 조회 경로를 3단계로 확장.

### 비범위
- 관리자 용어 CRUD API와 화면. 현재는 마이그레이션으로만 데이터를 넣는다.
- Space 구독 설정 API와 화면. 스키마와 조회 규칙만 준비하고 기본값(전체 구독)으로 동작한다.
- 동의어·부분일치 매칭. 현재와 동일하게 대소문자 무시 완전 일치만 지원한다.
- 공용 용어의 `embedding_chunks` 색인. `SourceType.GLOSSARY`는 이미 존재하지만 이번에는 연결하지 않는다.

## 조회 규칙

용어 설명 요청은 아래 순서로 처리한다. 앞 단계에서 결과가 나오면 뒤 단계는 실행하지 않는다.

1. **Space 등록 용어** — `domain_terms`에서 해당 Space의 `ACTIVE` 용어를 완전 일치로 조회. `model = "local-glossary"`.
2. **구독 분야 공용 용어** — 구독 중인 `GlossaryCategory`의 `shared_domain_terms`를 완전 일치로 조회. `model = "shared-glossary"`, 응답 `sources[].title`은 분야명.
3. **AI 게이트웨이 폴백** — 기존 동작과 동일.

여러 분야에 같은 용어가 있으면 `display_order`가 앞선 분야를 선택한다. 같은 입력에 항상 같은 결과를 돌려주기 위한 결정론적 규칙이다.

## 권한

구독하지 않은 분야는 SQL의 조회 조건에서 제외되므로 AI 컨텍스트 조립 이전에 걸러진다. 프롬프트로 숨기는 방식이 아니며 `.specify/memory/constitution.md` 5항(권한 선필터)과 `NFR-AZ-01`을 만족한다.

공용 용어는 Space 소유 데이터가 아니고 회의 내용을 포함하지 않으므로, 회의 단위 접근 제어(헌법 3항)의 대상이 아니다. 다만 조회 진입점은 기존과 동일하게 `AiSearchScopeResolver.meetingScope()`로 회의 접근 권한을 먼저 확인한 뒤에만 실행된다.

## 관련 요구사항

- `FR-TERM-02` 사전 우선 제공 — 공용 용어 히트 시 LLM을 호출하지 않는다.
- `FR-TERM-03` 미등록 LLM 호출 — 1·2단계에서 못 찾은 용어만 게이트웨이로 보낸다.
- `FR-TERM-04` 근거 범위 제한 — 구독 분야 밖의 용어는 근거로 사용하지 않는다.
- `FR-TERM-05` 용어 사전 관리 — 관리자 관리 기능은 후속 작업.
- `NFR-COST-01` — 사전 적중률이 올라가면 LLM 호출량이 줄어든다.

## 검증 기준

- 구독 중인 분야의 용어를 요청하면 사전 정의가 반환되고 게이트웨이가 호출되지 않는다.
- 같은 용어가 Space와 공용 사전에 모두 있으면 Space 정의가 반환된다.
- 구독하지 않은 분야의 용어는 사전에서 조회되지 않고 게이트웨이로 넘어간다.
- V1부터 최신 버전까지 마이그레이션이 순서대로 적용된다.
