## Blocking Decisions

- Q-009, Q-010, Q-015는 T030에서 결정됐다. Auth Service runtime은 이 계약을 구현하는 T031~T035 순서를 따른다.
- Q-016은 T032의 Auth revoke-all/revoke event와 T035의 실제 AuthSession ID/BFF 사용자 session index를 선행한 뒤 T024에서 모든 기기 로그아웃으로 구현했다.
- Q-017은 T032에서 계약·runtime에 반영한다. 이미 폐기된 동일 요청의 멱등 재시도를 위해 current AuthSession row의 소유자 결합은 유지하되 신규 active session 폐기는 최근 인증 검증을 계속 요구한다.
- Q-018과 Q-019는 T034에서 Core projection, 오프라인 이관·대사 도구와 강제 재로그인 운영 경계로 구현한다.
- Q-020과 Q-021은 권장안으로 결정됐다. T035는 external resource ID와 internal Auth UUID를 분리하고 동기 Core projection 성공을 Browser session 생성의 선행 조건으로 구현한다.
- Q-022는 T024 준비에서 결정됐다. 재인증 증명과 시각은 Browser가 `logout-all`에 직접 보내지 않고 전용 Browser→BFF→Auth 경계에서 검증하며, legacy provider에서는 불완전한 local-only 전체 로그아웃을 성공으로 위장하지 않는다.
- Q-012, Q-023, Q-025~Q-028은 NonProd V2 Terraform 기준으로 결정됐다. Q-013과 Q-024는 기반 리소스 구현을 막지 않지만 관련 autoscaling/장애 기준 또는 정식 public edge 출시를 막는다. Q-023 구현은 T047과 ECS Service 연결의 선행 작업이다.
- Q-029는 AI 전용 Envoy sidecar로 결정됐다. T047-B의 offline CA/cert-loader/secret delivery 뒤 T047-C2에서 loopback Uvicorn, Envoy SPIFFE RBAC와 FastAPI 재검증을 구현하고, T047-D runtime evidence 전에는 정상 runtime gate를 열지 않는다.

## Decisions

- D-001: 기존 `sessionStorage + Bearer` 흐름은 Current Prototype 호환 경로이며 목표 계약은 `specs/002-bff-auth-msa/contracts/*`가 대체한다.
- D-002: 외부 브라우저 API path는 `/api/v1/*`를 유지하고 BFF가 현재 Backend 또는 추출된 서비스로 명시적으로 라우팅한다.
- D-003: 브라우저-BFF는 쿠키 세션과 CSRF, BFF-Resource Service는 내부 access token을 사용한다.
- D-004: BFF 세션에는 token 원문 대신 Token Bundle 참조를 두고 Token Bundle은 AWS KMS 경계로 암호화한다.
- D-005: Auth Service는 User/AuthIdentity/AuthSession과 refresh hash/revoke를 소유하고 업무 RBAC/ACL은 소유하지 않는다.
- D-006: Resource Service는 Auth Service에 매 요청 동기 조회하지 않고 access JWT를 로컬 검증한다.
- D-007: Google ID credential은 검증 뒤 보관하지 않고 내부 MeetingMind token과 BFF 세션만 생성한다.
- D-008 (Superseded): AWS EKS 단일 리전 Multi-AZ 선택은 2026-07-23 ADR 002의 ECS Fargate 결정으로 대체됐다. 멀티리전은 계속 별도 재해복구 스펙으로 둔다.
- D-009: LiveKit Cloud 장애는 회의 metadata/보고서/AI 저장 데이터를 mock 성공으로 대체하지 않고 실시간 기능 unavailable로 격리한다.
- D-010: 점진 전환 중 현재 Backend DB와 API를 즉시 삭제하지 않고 compatibility adapter와 rollback window를 유지한다.
- D-011: 일반 BFF 세션은 유휴 60분/절대 12시간, Remember me 세션은 7일 sliding 유휴/14일 절대 만료를 사용한다. 모든 sliding 갱신은 최초 로그인 기준 절대 만료를 넘지 않는다.
- D-012: Token Bundle payload는 bundle/session/version을 인증 데이터로 묶은 AES-256-GCM envelope encryption을 사용한다. 운영 data key는 AWS KMS와 ECS 서비스별 Task Role로 생성·복호화하고, local/test adapter는 외부 주입한 256-bit AES master key만 허용한다.
- D-013: Phase 1의 현재 Backend는 안정된 논리 AuthSession ID를 응답하지 않으므로 Web BFF가 브라우저 로그인마다 호환용 `authSessionId`를 생성해 BffSession/TokenBundle만 묶는다. 이 값은 브라우저나 현재 Backend로 전달하지 않으며 Auth Service 추출 시 서버 발급 ID로 대체한다.
- D-014: Browser/Core 외부 사용자 ID는 `user-{Auth UUID}`를 유지한다. Auth UUID는 JWT `sub`, BFF 내부 session attribute와 Spring Session principal index, Core `users.auth_user_id`에서만 사용한다.
- D-015: 신규 Auth User의 Core projection은 BFF가 인증 성공 직후 동기 생성한다. Core는 target JWT와 workload identity를 함께 검증하고 `sub == authUserId`, `resourceUserId == "user-" + authUserId`일 때만 멱등 upsert한다. projection 실패 시 BFF는 Browser session을 만들지 않고 AuthSession을 best-effort revoke한다.
- D-014: Browser session cutover 이후 rollback은 direct Backend가 아니라 동일 cookie/Redis/Token Vault 계약을 사용하는 안정 BFF release로 수행한다. 신규 release는 readiness drain 뒤 ingress traffic weight를 0으로 내리고, Browser token/Bearer 코드는 복원하지 않는다.
- D-015: Refresh credential은 AuthSession별 한 family와 1회용 lineage를 사용한다. 사용된 credential 재사용은 grace 없이 해당 AuthSession/family 전체를 revoke하고 durable event를 기록하며 다른 기기의 AuthSession은 유지한다.
- D-016: Access는 KMS RSA-2048 `RS256`으로 서명한 audience별 10분 JWT다. 각 JWT는 단일 Resource Service audience와 `iss/sub/sid/jti/iat/nbf/exp/ver`를 필수로 가지며 업무 권한 원본은 포함하지 않는다.
- D-017: 현재/전체 로그아웃과 보안 폐기는 Auth DB revoke와 transactional outbox를 함께 커밋한다. Resource Service는 at-least-once revoke event를 idempotent하게 소비해 `sid`를 access 만료까지 로컬 denylist에 보관한다.
- D-018: 내부 서비스 호출은 mTLS SPIFFE workload identity, 서비스별 Security Group과 principal/endpoint allowlist를 함께 사용한다. 모든 기기 로그아웃은 최근 10분 인증 또는 local/Google 재인증을 요구한다.
- D-019: Core의 업무 식별자 `users.id`는 문자열 PK로 유지하고 Auth subject용 `users.auth_user_id UUID`를 projection으로 둔다. canonical legacy ID만 결정적으로 변환하고 비정형 ID는 수동 정리 없이는 Auth로 이전하지 않는다.
- D-020: T034는 별도 source/target JDBC 연결을 사용하는 오프라인 도구로 User/AuthIdentity snapshot과 최종 delta를 이관한다. dry-run/apply/verify와 exact reconciliation을 제공하며 DB link, runtime dual-write와 legacy AuthSession 변환을 사용하지 않는다.
- D-021: 모든 기기 로그아웃의 step-up 인증은 세션 비생성 전용 endpoint를 사용한다. Auth Service가 현재 AuthSession/User와 local/Google identity를 결합 검증해 서버 시각만 반환하고, Auth 전체 revoke의 durable commit 뒤 BFF가 Auth UUID Spring Session index로 다른 세션을 먼저, 현재 세션을 마지막에 삭제한다.
- D-022: NonProd V2 네트워크는 `ap-northeast-2`의 `10.20.0.0/16` VPC로 시작하고 2개 AZ에 Public, Private app, Data subnet을 둔다. Regional NAT Gateway automatic mode, private route, S3 Gateway Endpoint를 포함한 새 V2 전체를 Terraform으로 관리한다.
- D-023: NonProd V2는 단일 ECS Fargate 클러스터에서 BFF/Auth/Core/AI/Realtime STT를 별도 ECS Service/Task Definition/Task Role/Security Group/7일 Log Group으로 격리한다. STT 업무 API `8083`은 Core SG만 허용하되 LiveKit Egress audio용 `/ws/egress-audio/*` WSS는 ALB SG와 짧은 수명의 1회용 token 경계로 별도 허용한다. 정식 edge는 Route 53→CloudFront/WAF→public ALB→BFF/STT target group이다.
- D-024: 기존 수작업 NonProd 리소스는 Terraform에 import하지 않는다. 같은 계정에 `nonprod-v2`를 병렬 구축하고 검증·전환·관측 기간이 끝난 뒤 사용자 별도 승인으로 기존 환경을 정리한다.
- D-025: V2 RDS는 기존 데이터 이전 없이 빈 PostgreSQL 16에서 시작한다. NonProd는 Single-AZ, encrypted backup과 deletion protection을 사용하고 서비스별 논리 database와 migration/runtime role을 분리한다.
- D-026: Terraform CLI `>=1.10,<2.0`과 S3 backend native `use_lockfile=true`를 사용한다. state bucket은 versioning, SSE-KMS, Block Public Access, TLS-only policy를 적용하고 신규 DynamoDB lock table은 만들지 않는다.
- D-027: RDS master는 RDS-managed secret, Valkey는 IAM authentication을 사용한다. Terraform은 그 밖의 Secrets Manager metadata, KMS/IAM 경계와 ECS secret ARN 참조만 관리한다. 실제 application/provider secret version은 사용자가 AWS Console에서 입력하며 `.tfvars`, plan, output과 Terraform state에 넣지 않는다.
- D-028: 도메인 발급 전 ALB DNS는 제한된 smoke test에만 사용한다. `Secure` cookie, ACM/HTTPS, CloudFront/WAF와 LiveKit WSS end-to-end 검증은 도메인 발급 후 출시 gate다.
- D-029: V2 공통 tag는 `Project=MeetingMind`, `Environment=nonprod-v2`, `ManagedBy=terraform`, `Repository=Meeting-Mind/MeetingMind`이며 공용 리소스의 `Service`는 `platform`이다.
- D-030: Q-023은 Cloud Map Private DNS `meetingmind.internal`과 직접 mTLS를 선택한다. 공통 내부 CA가 서비스별 SPIFFE URI SAN 인증서를 발급하고, NonProd에서는 Secrets Manager version 교체 후 ECS force deployment로 수동 rotation한다. 내부 주소는 `auth.meetingmind.internal:8082`, `core.meetingmind.internal:8080`, `ai.meetingmind.internal:8000`, `stt.meetingmind.internal:8083`이며 principal/endpoint allowlist와 서비스별 Security Group을 함께 적용한다.
- D-031: ECS runtime은 단일 boolean으로 다섯 서비스를 동시에 시작하지 않는다. 전역 `enable_runtime_services` kill switch와 명시적 `runtime_enabled_services` allowlist를 함께 요구하고, allowlist에 포함된 서비스마다 ECR `sha256` digest와 desired count를 검증한다. Cloud Map namespace/service는 runtime off 상태의 foundation에서 먼저 만들되 Task instance 등록은 해당 ECS Service가 활성화된 뒤에만 수행한다.
- D-032: NonProd mTLS는 암호화된 offline root/intermediate CA, 서비스별 Secrets Manager TLS bundle과 전용 최소 ARM64 `meetingmind-cert-loader`를 사용한다. AI는 Envoy sidecar가 `ai.meetingmind.internal:8000`에서 mTLS와 exact Core SPIFFE를 검증하고 loopback Uvicorn `127.0.0.1:8001`로 전달한다. leaf rotation은 `AWSPENDING` 검증, `AWSCURRENT` 승격과 ECS force deployment로 수행한다. Production은 AWS Private CA 또는 자동화 CA를 별도 승인하며 NonProd CA/private key를 재사용하지 않는다.
- D-033: T047-D/T048-V evidence를 근거로 private mTLS runtime promotion과 BFF/public release gate를 분리한다. `runtime_gates_acknowledged`와 `internal_mtls_runtime_verified`는 Auth/AI/Realtime STT/Core의 public-traffic 없는 promotion만 허용한다. Q-013, BFF Valkey IAM token/connection/TLS preflight, T047-E, T048와 T049는 `release_gates_acknowledged`로 묶고, 이 값이 false인 동안 BFF, public listener와 autoscaling을 Terraform에서 거부한다.
- D-034: 정식 운영 전환과 별개로 2026-07-26 NonProd 배포 smoke를 허용한다. `release_gates_acknowledged=false`와 autoscaling off를 유지하면서 별도 `deployment_smoke_gates_acknowledged`가 BFF 1개, CloudFront 기본 HTTPS 도메인, private S3 정적 origin과 `/api/*` BFF origin만 한시적으로 연다. BFF는 mTLS, Valkey IAM/TLS와 private subnet/no-public-IP 경계를 유지하고 ALB는 CloudFront origin-facing managed prefix list에서만 접근 가능해야 한다. custom domain, Route 53/ACM, WAF 정식 정책, Multi-AZ/SLO/장애·부하 검증과 Production 전환은 이 smoke의 완료 조건이 아니며 T048/T049/T059 정식 release gate를 완료로 표시하지 않는다.
- D-035: 사용자가 발급·검증한 `us-east-1` ACM 인증서와 외부 가비아 DNS를 prerequisite로 사용해 NonProd CloudFront viewer domain을 `app.meetingmind.co.kr`로 연결한다. Terraform은 CloudFront alias, 기존 인증서 ARN 참조와 `TLSv1.2_2021`을 선언해 수동 설정의 drift를 방지하되 Route 53, ACM 발급·DNS 검증 레코드와 가비아 zone은 관리하지 않는다. 이 연결은 T059-S3 browser smoke 보강이며 WAF, ALB HTTPS, LiveKit WSS, autoscaling/SLO·장애·부하 검증과 Production 전환을 포함한 정식 T059 release gate를 완료하지 않는다.
- D-036: NonProd Google 로그인에서 Frontend가 발급받는 Google ID token의 audience와 Auth Service 허용 목록을 같은 공개 OAuth web client ID로 명시한다. Terraform의 `auth_google_client_ids`를 Auth ECS environment `AUTH_GOOGLE_CLIENT_IDS`로 전달하고, browser-facing BFF runtime은 빈 목록으로 plan할 수 없게 한다. OAuth client secret은 이 변수에 저장하지 않는다.
- D-037: Phase 1 LiveKit 토큰·transcription Browser route는 LiveKit 전용 timeout/circuit/error 정책을 유지하되 실제 API와 회의 ACL을 소유하고 `meetingmind-core` audience를 검증하는 Core로 전달한다. BFF route는 downstream 정책과 access JWT audience를 분리하고, 별도 LiveKit Resource Service가 route를 소유하기 전에는 `meetingmind-livekit` access를 Core에 보내지 않는다.
- D-038: `app.meetingmind.co.kr` NonProd browser smoke에서 Realtime STT를 검증하기 위해 `/ws/egress-audio/*`만 CloudFront→ALB→Realtime STT로 전달한다. STT는 명시적 HTTPS `PUBLIC_WS_BASE_URL`, session-bound HMAC token, ALB SG 전용 ingress를 요구한다. 내부 업무 API는 계속 Core mTLS만 허용하고 WebSocket path 이외의 STT public route는 열지 않는다. 이 한정 경로는 정식 WAF/autoscaling/SLO·부하·장애 gate를 완료한 것으로 간주하지 않는다.
- D-039: Phase 1의 Meeting/Project AI Browser API도 실제 endpoint와 Meeting/Space ACL을 Core가 소유한다. BFF는 AI 전용 timeout/circuit/error 정책을 유지하되 Core가 검증하는 `meetingmind-core` access JWT를 전달한다. 별도 AI Resource API가 Browser 계약과 권한 선필터를 소유하기 전에는 `meetingmind-ai` access JWT를 Core에 보내지 않는다.
- D-040: 분리 배포에서 Realtime STT DB의 transcript/status/segment가 authoritative source다. Core는 사용자 access와 Meeting ACL을 먼저 검증한 뒤 Core→STT mTLS 내부 API로 확정 segment와 partial을 읽어 Browser dialogue를 구성한다. Core DB의 시작 row는 in-process rollback 호환과 ACL 연결을 위해 유지하되 remote mode의 화면 데이터 원본으로 사용하지 않는다. AI/report/embedding이 사용할 durable Core projection 또는 STT source 직접 조회 계약은 별도 task로 완료하기 전까지 미완료 경계로 명시한다.
- D-041: 회의방 `Leave`는 Meeting 종료와 분리한다. 브라우저가 소유한 microphone track의 STT session을 정상 종료하고 session ID를 폐기하며, 재참여는 새 track으로 terminal transcript를 재개한다. 기존 segment와 최초 시작 시각은 보존하고 새 segment 시간은 기존 마지막 구간 뒤에서 이어진다. 사용자용 화자명은 인증된 참여자 display name이며 STT session/egress/track UUID를 UI label로 노출하지 않는다.
- D-042: Realtime STT mapper가 assembler에 전달하는 `PARTIAL.text`는 provider 형식과 관계없이 같은 provider segment의 최신 전체 발화 snapshot이다. 같은 partial ID의 후속 event는 이전 snapshot을 교체하고, assembler는 provider가 수정한 가설을 delta로 간주해 문자열을 누적하지 않는다. final event와 마지막 partial fallback은 기존 멱등 처리를 유지한다.
- D-043: Realtime STT DB는 transcript authoritative source로 유지하고 Core DB는 report/task/AI/RAG용 derived projection을 저장한다. Core는 인증·Meeting ACL 검증 후 stop 성공 응답에서 Core→STT mTLS 전체 snapshot을 읽고, STT speaker/segment ID와 sequence를 보존해 해당 meeting projection을 하나의 transaction으로 교체한다. 같은 snapshot 재시도는 no-op이며, 최초 `COMPLETED` 전환은 DB trigger가 embedding job을 생성하고 이미 완료된 snapshot이 수정된 경우만 `FULL_REINDEX`를 생성한다. STT stop의 terminal 멱등 응답은 STT 완료 후 Core projection 전 장애가 난 경우 같은 stop 요청으로 복구할 수 있게 한다.
