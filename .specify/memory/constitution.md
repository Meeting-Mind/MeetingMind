이 문서는 MeetingMind의 불변 제품 원칙과 에이전트 판단 기준을 정의하기 위한 Markdown 문서이다.

# MeetingMind Constitution

이 문서는 MeetingMind의 프로젝트 헌법이다. 기능 스펙, 기술 계획, 작업 목록, 구현은 이 원칙을 위반할 수 없다.

## 1. 제품 정체성

MeetingMind는 단순 회의록 도구가 아니라 프로젝트 단위 지식 관리 플랫폼이다. 모든 기능은 회의 데이터를 프로젝트 의사결정, 업무, 문서, 검색 가능한 지식으로 전환하는 데 기여해야 한다.

## 2. Space 우선 구조

프로젝트는 Space로 관리한다. 사용자는 Space에 초대되어 참여하고, 회의/문서/지식/권한은 Space 컨텍스트 안에서 해석한다.

## 3. 회의 단위 접근 제어

회의는 회차별 접근 권한을 가진다. 회의 참여자 또는 명시적으로 권한을 받은 사용자만 해당 회의 STT, 보고서, 결정사항, Action Item에 접근할 수 있다.

## 4. AI 검색 범위 분리

Meeting AI는 현재 회의의 STT, 보고서, 결정사항, Action Item만 검색한다.
Project AI는 Project Knowledge와 사용자가 접근 가능한 회의 데이터만 검색한다.
두 AI의 검색 범위는 UI, API, 프롬프트, RAG 쿼리 단계에서 모두 분리되어야 한다.

## 5. 권한 선필터 원칙

RAG, 키워드 검색, AI 컨텍스트 조립 전 사용자 권한을 먼저 적용한다. AI에게 전달된 뒤 프롬프트로 숨기는 방식은 권한 통제로 인정하지 않는다.

## 6. 근거 기반 응답

AI 응답은 제공된 컨텍스트에 근거해야 한다. 근거가 없는 질문에는 추정하지 않고 확인 불가로 답한다. 가능하면 회의 시간, 문서명, 결정사항 ID 등 출처를 함께 제공한다.

## 7. 데이터 보존 최소화

음성 원본은 기본적으로 장기 보관하지 않는다. STT 원문, 보고서, 첨부 파일은 관리자가 설정한 보관 정책에 따라 저장/삭제한다.

## 8. 공식 지식과 회의 기록의 분리

Project Knowledge는 프로젝트의 공식 최신 상태다. 회의 기록은 의사결정의 근거와 흐름이다. Project AI는 둘을 구분해서 답변해야 한다.

## 9. 현재 구현 경계

현재 저장소는 프로토타입이다. Frontend는 mock fallback을 포함하고, Backend는 workspace 데모 API와 LiveKit 토큰 발급을 제공하며, AI 서버는 Meeting AI 질문 응답의 최소 구현을 제공한다. 문서와 구현은 이 경계를 숨기지 않는다.

## 10. 검증 가능한 변경

모든 기능 변경은 사용자 가치, API/데이터 계약, 검증 방법을 가져야 한다. 검증 없이 완료된 것으로 간주하지 않는다.
